# CloudSentinel AI

Cloud security misconfiguration scanner: a custom rules engine (FastAPI) that checks a cloud configuration (JSON) and reports findings with severity, impact, and remediation. Angular dashboard and AI explanation layer come next.

> All sample data is fictional. Do not upload real credentials or real cloud configs.

## Run the backend

```bash
cd backend
python -m venv venv
venv\Scripts\activate            # Mac/Linux: source venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --reload
```

Open http://127.0.0.1:8000/docs to try the API.

## Run the tests

```bash
cd backend
python -m pytest
```

## CloudFormation scanning (v2)

The scanner now reads real AWS CloudFormation templates (JSON). A parser converts supported resources
(S3 Bucket, EC2 SecurityGroup, RDS DBInstance, IAM Policy/ManagedPolicy/Role) into a normalized model,
and 15 rules analyze the actual properties (ports, CIDR ranges, policy statements) instead of ready-made flags.

Each check returns one of four statuses:

| Status | Meaning |
|---|---|
| PASS | the available evidence shows the check passed |
| FAIL | the available evidence shows a violation |
| UNKNOWN | not enough information (dynamic value such as `Ref` / `Fn::If`, or a missing property whose default is unclear) |
| NOT_APPLICABLE | the rule does not apply to this resource |

Resources of unsupported types are listed separately and are not scanned.
Templates must be JSON (YAML is not supported yet).

Run the evaluation on the sample templates (compares results to hand-written expected results):

```bash
cd backend
python evaluate.py
```

## Real-world validation

The scanner was run on the 141 CloudFormation JSON templates in AWS's public sample repository
(`aws-cloudformation/aws-cloudformation-templates`; 13 other JSON files there are not templates and are correctly rejected).
Reproduce it with:

```bash
git clone --depth 1 https://github.com/aws-cloudformation/aws-cloudformation-templates.git
cd backend
python scan_folder.py ../aws-cloudformation-templates
```

What that run showed (about 15 templates were reviewed by hand against the source):

- No crashes. 97 of 141 templates contain at least one supported resource; 203 resources were analyzed and 817 were not (unsupported types such as VPC, EC2 instances, Lambda, S3 bucket policies).
- Bugs found and fixed, each with a regression test: numeric `IpProtocol: -1` was treated as unknown (missed an open security group); Aurora cluster members were reported as unencrypted; log buckets were reported as missing access logging; `Fn::ForEach` and `Rain::Module` resources made the whole template fail to load.
- Template parameters with a default (for example `SSHLocation = 0.0.0.0/0`) are now evaluated with that default, and the result says so. This is why 25 security groups in the AWS samples are reported as open to the internet.

Known gaps: YAML templates (about half of that repository), S3 bucket policies, most resource types, and resources generated by `Fn::ForEach` or Transforms (reported as not analyzed). There is no independent ground truth for the real templates, so precision on them is only spot-checked.

## API

| Method | Path | What it does |
|---|---|---|
| GET | `/api/samples` | List sample environments |
| GET | `/api/samples/{id}` | Get one sample config |
| POST | `/api/scan/sample/{id}` | Scan a sample environment |
| POST | `/api/scan` | Scan an uploaded config: `{"config": {...}}` |
| GET | `/api/cfn/rules` | Rule catalog (15 rules) |
| GET | `/api/cfn/samples` | List sample CloudFormation templates |
| GET | `/api/cfn/samples/{id}` | Get one sample template |
| POST | `/api/cfn/scan/sample/{id}` | Scan a sample template |
| POST | `/api/cfn/scan` | Scan an uploaded template: `{"template": {...}}` |
| POST | `/api/cfn/compare` | Before/after: `{"before": {...}, "after": {...}}` |

## Project structure

- `cfn/` - CloudFormation engine: `parser.py` (template to normalized model), `model.py`, `rules.py` (15 rules), `scanner.py`, `compare.py`.
- `samples_cfn/` - fictional CloudFormation templates (insecure, insecure-fixed, mixed, secure).
- `ground_truth.py`, `evaluate.py`, `test_cfn.py`, `test_cfn_api.py` - expected results, evaluation and tests for the CloudFormation engine.
- `rules.py` - the original 12 flag-based rules (legacy) (CLOUD-001 to CLOUD-012). Each rule is one function.
- `scanner.py` - runs all rules, sorts findings by severity, builds the summary.
- `samples.py` - three fictional environments (insecure, mixed, well-configured).
- `main.py` - FastAPI app and endpoints.
- `test_scanner.py` - tests for rules, scanner, and API.

## Add a new rule

1. Write a function in `rules.py` that takes `config` and returns a finding (via `_finding(...)`) or `None`.
2. Add it to `ALL_RULES`.
3. Add a test.
